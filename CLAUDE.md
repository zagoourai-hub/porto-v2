# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (`pnpm-lock.yaml`, `packageManager` pinned in `package.json`).

- `pnpm dev` — dev server (http://localhost:3000)
- `pnpm build` / `pnpm start` — production build / serve
- `pnpm lint` — ESLint 9 flat config (`eslint.config.mjs`, extends `eslint-config-next`)

There is no test runner configured. Type-check with `pnpm exec tsc --noEmit`.

## Next.js version caveat

`AGENTS.md` is authoritative: this is Next.js 16.x / React 19 with breaking changes versus training data. Before writing Next code, read the matching guide in `node_modules/next/dist/docs/` (`01-app` is the one that applies here; `index.md` is the entry point).

## Architecture

Single-page portfolio on the App Router. Currently only `app/layout.tsx`, `app/page.tsx` and `app/globals.css`; `app/page.tsx` is still the create-next-app placeholder.

- **`next.config.ts`** enables `cacheComponents` and `partialPrefetching`, so the Cache Components / PPR model applies: dynamic data access must be wrapped in `<Suspense>` or opted into caching with `use cache`, otherwise the build errors.
- **Tailwind v4 via Turbopack**: there is no `postcss.config` and no `tailwind.config`. CSS goes through `@tailwindcss/turbopack`, wired in `next.config.ts` under `turbopack.rules["*.css"]`. Tokens live in `app/globals.css` (`@import "tailwindcss"`, `@theme inline`). Don't add a PostCSS setup.
- **Typed props**: `app/layout.tsx` uses the global `LayoutProps<"/">` helper (generated by Next typegen into `.next/types`), not hand-written prop types. Pages can use `PageProps<"/route">` the same way.
- **Fonts** are loaded with `next/font/google` in `layout.tsx` and exposed as CSS variables on `<html>`.

## Design system

`docs/DESIGN.md` is the design source of truth: sharp/brutalist-editorial, single red signal color (`primary`) plus indigo `secondary`, **zero border radius**, `0.5px` hairline borders, Geist Sans/Mono, OKLCH palette. It specifies a daisyUI theme named `portfolio` (`@plugin "daisyui/theme"`). Follow it for any UI work (the repo's daisyUI skill also applies to HTML/JSX).

Known gaps between docs and code (verify before relying on either):

- `daisyui` is **not** in `package.json` and `globals.css` has no `@plugin` / `portfolio` theme yet.
- `globals.css` still sets `body { font-family: Arial, ... }`, which DESIGN.md says to remove so the theme font applies; `--font-sans` points at `--font-geist-sans`, but `layout.tsx` currently loads only `Geist_Mono` and `Bebas_Neue` (the latter bound to `--font-ebas-neue`, a likely typo of `--font-bebas-neue`).
- `layout.tsx` metadata is still the "Create Next App" default.
- `public/assets/bg-hero.png` is the hero background asset.
